# Achmage Bases Look 1.4.0 — 노트에 넣은 베이스에도 표 서식

노트 안에 넣은 베이스(`![[베이스.base#뷰]]`, ```` ```base ```` 코드 블록)에서도 베이스에서 정한 표 서식이 그대로 보이고, 그 자리에서 우클릭으로 서식을 고치고 열과 행을 맞출 수 있습니다.

- **서식이 그대로 보입니다.** 베이스에 저장된 머리글·열·행·칸 서식이 노트에 넣은 표에도 똑같이 칠해집니다.
	- 읽기 모드와 라이브 프리뷰, 링크에 마우스를 올렸을 때 뜨는 미리보기, 캔버스의 베이스 카드에서도 같습니다.
	- 라이트·다크 색도 테마마다 따로 보입니다.
- **그 자리에서 고칩니다.** 노트 속 표의 머리글·칸·드래그로 고른 칸을 우클릭하면 **셀 서식…**, 열 너비·행 높이 맞추기, 서식 지우기가 베이스 탭과 똑같이 뜹니다. 경계 더블클릭과 행 높이 끌기도 됩니다. 명령 팔레트의 표 명령 3개는 마지막으로 누른 노트 속 표에도 작동합니다.
- **저장은 Obsidian이 합니다.** 노트 속 표에서 바꾼 것은 Obsidian이 그 표를 저장하는 곳에 들어갑니다.
	- 파일로 넣은 베이스(`![[…base]]`)는 그 `.base` 파일에 저장됩니다. 베이스 탭과 노트가 함께 열려 있으면 서로 따라 바뀝니다.
	- 코드 블록 베이스는 노트 속 그 코드 블록에 저장됩니다. Obsidian이 저장할 때 코드 블록을 자기 방식으로 다시 쓰므로(열 너비를 바꿀 때와 같음) 줄 모양이 조금 바뀔 수 있습니다.
- **글자 위를 우클릭해도 표 메뉴.** Bases는 글자 칸을 늘 편집 칸으로 그려서, 지금까지는 칸의 빈 곳을 눌러야 서식 메뉴가 떴습니다.
	- 이제 글자 위를 눌러도 뜨고, 우클릭만으로 칸이 편집 상태로 바뀌지 않습니다.
	- 편집 중인 칸은 원래 편집 메뉴(맞춤법·잘라내기·붙여넣기)를 그대로 씁니다. 칸 안의 링크도 원래 링크 메뉴입니다.
	- 라이브 프리뷰의 노트 속 표에서는 에디터 메뉴 대신 표 메뉴가 뜹니다.
- **열 너비 맞춤 바로잡기.** 글자 칸이 열 폭만큼 늘어난 채로 재져서, 맞춤이 넓히기만 하고 줄이지는 못했습니다. 이제 글자 폭을 재서 넓은 열은 줄이고 좁은 열은 넓힙니다. 화면 밖 행을 글자로 어림할 때 쓰는 칸 여백도 실제 값으로 바로잡았습니다.
- **그대로인 것.** 썸네일·그룹 색·조절 패널은 지금처럼 베이스 탭에서만 꾸밉니다. 노트 속 베이스는 그 밖에는 순정 모습입니다. 코드 블록 베이스의 행·칸 서식은 노트 이름을 바꿔도 따라가지 않습니다(`.base` 파일은 따라갑니다).

**검증:**
- 자동 검사 70개를 통과했습니다(신규 10개: 노트 속 베이스에 서식 반영, 바뀐 설정만 쓰기, 지운 설정 지우기, 정렬·필터 같은 뷰 고유 항목 무시, 베이스 전체 설정, 뷰가 다르면 손대지 않기, 서식 읽기). TypeScript, Obsidian 심사 규칙 전체(`recommended`) 0건, 빌드, 버전 일치, 비밀정보 검사도 통과했습니다.
- Windows / Obsidian 1.15.1 테스트 볼트에서 다음을 확인했습니다.
	- 파일 임베드와 코드 블록(읽기 모드·라이브 프리뷰), 호버 미리보기, 캔버스 카드에 서식이 칠해집니다. 라이트↔다크 전환도 확인했습니다.
	- 머리글·칸·선택 범위 우클릭 메뉴에서 서식을 바꾸면 베이스 파일(약 1초 뒤)과 노트 코드 블록에 저장됩니다.
	- 열 경계 더블클릭(넓히기·줄이기·자동 너비로 되돌리기)과 행 경계 더블클릭 결과가 파일에 저장됩니다.
	- 베이스 탭과 노트 속 표가 서로 따라 바뀝니다(베이스 탭이 저장한 뒤 약 2초).
	- 노트를 열고 미리보기를 띄우고 테마를 바꾸기만 해서는 베이스와 노트가 바뀌지 않습니다. 노트 속 표가 있는 노트에 40글자를 입력하는 동안 플러그인은 한 번도 다시 칠하지 않습니다.
	- 플러그인을 끄면 노트 속 표의 서식이 바로 사라지고, 다시 켜면 돌아옵니다.
	- 베이스 탭의 1.3.0 기능(메뉴·서식·지우기·열 맞춤)도 그대로입니다.
- 모바일과 팝아웃 창은 실기로 확인하지 않았습니다.

---

- **Formats show in embedded bases.** Header, column, row and cell formats set in a base now show where the base is embedded: `![[file.base#view]]` in a note, a ```` ```base ```` code block, a hover preview and a canvas card, in reading view and live preview, with each theme's own colors.
- **Change them right there.** Right-click a header, a cell or a dragged selection of an embedded table: **Format cells…**, fitting columns and rows and clearing formats work as in a Bases tab, and so do double-clicking a column or row line and dragging the row line. The three table commands work on the embedded table used last.
- **Saved by Obsidian, where it keeps the base.** Changes made in an embedded file base go to its `.base` file; an open Bases tab and the note follow each other. Changes made in a code block go to that code block, which Obsidian rewrites in its own layout when it saves (as when a column is resized there).
- **Right-clicking the text of a cell opens the table menu.** Bases draws every text cell as a field, so the menu used to open only on the empty part of a cell. Now the text works too, without putting the cell into editing; a cell being edited keeps its editing menu, and links keep theirs. In live preview, the table menu replaces the editor's menu inside embedded tables.
- **Fitting a column measures text cells by their text.** They were measured at the column's width, so fitting could only widen a column; it now narrows wide columns as well. The cell padding used to estimate rows off screen is measured correctly too.
- **Unchanged:** thumbnails, group colors and the look panel stay in Bases tabs. Row and cell formats of a code block base do not follow renamed notes (those of `.base` files do).
